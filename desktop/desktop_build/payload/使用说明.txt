一碰传 6.2.5（nfctap/3）
========================

本文件随安装程序附带，位于程序目录。产品版本：桌面端 / 安装包为 6.2.5，
随包手机端 APK 以实际内嵌为准（当前为 6.2.4 / versionCode 14，两端版本号独立）；
线缆协议仍是
nfctap/3、协议版本 3.0.0，手机端会严格比对协议版本，5.x 及更早的客户端不再兼容。

6.2.5 更新：合并「文件目录」与「接收文件」两个页签，界面精简为三个页签：
接收文件 / 发送文件 / 服务与设置。
  「接收文件」页现在是左右分栏：左侧是最近传输记录表格，右侧实时预览——
  点选某条记录，图片直接显示，其它类型显示类别、大小与时间；双击打开文件。
  原「文件目录」页的能力（查看已接收文件、图片预览、双击打开）已并入本页。
  拖出能力保持不变：按住已保存的文件可拖到微信 / 钉钉 / 资源管理器。
  transfer.log.jsonl 超过 5 MB 自动轮转，保留最近 5 份（.1 最新）。

6.2.4 更新：随包手机端升级到 6.2.3，修掉「碰标签时被系统文件选择器抢走
接收方向」的问题（电脑有待发文件时，手机会先走接收，不再误弹选文件框）。
桌面端功能与 6.2.3 一致。

6.2.3 新增：接收文件可拖出到微信 / 钉钉 / 资源管理器。
  「接收文件」页里按住某条已保存的文件拖出窗口，松手即把该文件交给外部程序：
  拖到聊天软件的输入框会变成发送该文件，拖到资源管理器 / 桌面会复制一份，
  和从资源管理器里拖文件完全一样（标准 Windows 文件拖拽，不是应用内拖放）。
  1. 拖动阈值与系统一致，按下后移动不足阈值不会触发；单击仍是原有的选中/预览，
     双击仍然是打开文件。
  2. 拖起后光标跟随一张「文件图标 + 文件名」的小卡片，可据此判断拖的是哪个文件。
  3. 只对已保存到本机的接收记录生效；仍在传输或未落盘的行不会被拖出。
  4. 原来的「把文件拖进窗口加入待发队列」保持不变：拖到表格外部/窗口空白处
     仍是入队发送，起点在表格行上才是向外拖出。
  其余功能与 6.2.2 一致。

6.2.2 安全修复：
  1. 配对入口只接受真实 NFC 标签。显式 Intent、网页自定义 scheme 或任何
     非 NFC 来源的 nfctap:// 链接一律拒绝；首次配对或换标签会弹窗确认，
     不会静默覆盖已有的 k / h / p。
  2. 配对密钥 k 不再进入 URL。浏览器免安装方案改为在页面输入框手动粘贴 k，
     访问日志对 k / token / ticket 等查询参数统一脱敏；自检结果不再写完整 URI，
     桌面端默认打码显示配对 URI，复制后 60 秒自动清空剪贴板。
  3. 版本号统一为 6.2.2，安装包内嵌手机端 APK 同步更新。

6.2.1 新增：开机自动启动。
  「服务与设置」页新增「开机自启」开关，默认关闭。开关状态直接读注册表
  HKCU\Software\Microsoft\Windows\CurrentVersion\Run 下的 NfcTapLink 值，
  用户手动改注册表或换机器后，界面显示的就是系统里的实际状态。
  自启动用当前运行程序的实际路径写入（用户级，不需要管理员）；安装目录变了，
  取消勾选再重新勾选即可把路径修正为新位置。
  开机自启时不弹主窗口、不抢焦点，直接驻留托盘，接收服务与蓝牙广播照常启动；
  双击托盘图标或从菜单「打开主界面」即可看到窗口。
  卸载安装包时会自动删除这条自启动项，不留残迹。
  其余功能与 6.2.0 一致。
反向发送（电脑 → 手机）：桌面端把文件拖进窗口（或点「选择文件」），
点「发送」后手机碰标签即可下载；
手机碰一下同一张 NFC 标签即可自动接收，无需在手机上点选文件。

一、首次使用（与旧版最大差别）
  1. 安装包不含任何长期密钥。首次启动桌面端时会在本机随机生成 256-bit 配对密钥，
     只保存在 %LOCALAPPDATA%\NfcTapLink\config.json，不随安装包分发。
  2. 在桌面端「服务与设置」页复制标签 URI，用写卡工具写入物理 NFC 标签（NTAG215）。
     旧版 5.x 标签全部失效，必须重写。轮换密钥后也必须重写标签。
  3. 配对 URI 含配对密钥，等同于「这台电脑的钥匙」：不要截图、不要发到聊天/邮件、
     不要把含 URI 的 adb 命令贴到日志或工单里。

二、桌面端能做什么
  1. 自动开启接收服务（HTTP 8765）与蓝牙 BLE 广播；手机碰标签后双向认证再传文件。
     若蓝牙组件缺失、蓝牙被关闭或适配器不支持广播，桌面端会直接写明原因和
     处理建议，并在后台自动重试；局域网 UDP 发现始终不受影响。
  2. 「接收文件」页列出已接收文件与传输记录；点选右侧直接预览（图片可看，
     其它类型显示类别、大小与时间），双击只打开安全白名单内的文件；
     脚本/可执行类一律只定位所在文件夹，不运行。
  3. 「接收文件」页按时间列出传输结果；按住在已保存的文件上可拖到微信 / 钉钉 /
     资源管理器；transfer.log.jsonl 超过 5 MB 自动轮转，
     保留最近 5 份（.1 最新），历史日志可继续回看。
  4. 「服务与设置」页启停服务、开关 BLE、开关开机自启、查看/复制配对 URI、打开数据目录。
     页签顺序为：接收文件 / 发送文件 / 服务与设置，默认停在接收文件。
  5. 「发送文件」页：
       把文件直接拖进窗口即可加入待发队列（也支持点「选择文件」）；
       一次可拖入多个文件，拖入时窗口会出现整屏落区高亮提示。
       → 点一次「发送」→ 队列里的文件按顺序逐个暂存到本机 outbox →
         手机每碰一次标签取走一个（加密下载）。
     过程中显示「正在发送 2/3：xxx.docx」这样的进度；
     单个文件失败（文件丢失、手机接收中断、等待确认超时）不会中断后续文件，
     全部结束后给出一次汇总：共几个、成功几个、失败几个，并列出失败文件名
     与具体原因；汇总里的「重试失败的 N 个文件」可把失败项直接再发一遍。
     手机接收成功后待发状态自动清空，不需要手动清理。
     「取消待发」会立刻中止整批并撤销队列，手机之后碰标签不再接收。
     协议同一时刻只保留一个待发文件，所以多文件是排队逐个发出的。
  6. 服务端按文件内容 sha256 去重；同一文件重复传会提示「已跳过重复保存」。
     1 GB 文件按 1 MB 分块流式写盘 / 流式发送，不再整体读进内存。
  7. 系统托盘：
       点窗口右上角 X 不退出程序，窗口收进系统托盘，接收服务与蓝牙广播继续
       在后台运行，手机照常碰标签传文件。
       托盘图标右键菜单：打开主界面 / 发送文件… / 退出。选「发送文件…」会直接
       拉起文件选择框，选完的文件自动进入「发送文件」页的待发队列。
       双击托盘图标恢复主界面；从托盘唤起时窗口会正常前置，不只是任务栏闪一下。
       收到文件时托盘弹出轻量提示，点提示直接打开主界面看「接收文件」记录。
       「退出」才是真正结束进程（会同时停止 HTTP 服务与蓝牙广播）。
       托盘图标为程序自绘，不依赖任何第三方图标库，配色与窗口暗色主题一致。

三、能传什么
  单个文件上限 1 GB（手机端、网页端需同步为同一上限）。落盘扩展名采用白名单；
  危险 / 活动脚本类（.html .svg
  .exe .bat .js .lnk 等）一律降级为 .bin，不会按可执行类型落盘。
  图片额外校验文件头，改扩展名混入的会降级 .bin。
  文件名会被清洗（空格、路径分隔符等），落盘名可能与原件不完全一致。
  服务端只负责落盘，不会自动打开或运行收到的文件。

四、文件存在哪
  数据目录：%LOCALAPPDATA%\NfcTapLink
  接收文件：%LOCALAPPDATA%\NfcTapLink\received
  待发暂存：%LOCALAPPDATA%\NfcTapLink\outbox（元数据 pending.json + 文件副本）
  传输日志：%LOCALAPPDATA%\NfcTapLink\transfer.log.jsonl（及 .1 ~ .5 轮转档）
  配对配置：%LOCALAPPDATA%\NfcTapLink\config.json
  程序装在安装目录（只读），数据放在用户目录（可写）；卸载不会删除数据目录。
  手机端接收位置：Android 10 及以上为「内部存储/Download/一碰传」；
  Android 9 及以下落在应用私有目录（文件管理器路径：Android/data/
  com.example.nfctaplink/files），可在手机端结果提示里看到实际路径。

五、手机端
  安装包内 mobile\NfcTapLink.apk 是随包手机端，可传到手机覆盖升级。
  首次打开会申请蓝牙与照片权限，请全部允许；升级安装后系统可能重置权限，
  若发现「找不到电脑」，打开一次主界面重新授权即可。
  碰标签时的行为：
    1. 先探测电脑上是否有待发文件：有就自动加密下载并保存，弹结果提示；
       电脑上没有待发文件则静默回落到原来的发送流程，不打扰用户。
    2. 原发送流程默认「每次碰标签选文件」：碰标签 → 手动确认要发的文件 → 发送。
       确认窗 5 秒倒计时结束 = 自动取消，不会自动发送；只有点「立即发送」才发。
  分享寄存用法不变：在文件管理器/微信/QQ/邮件里分享文件到「一碰传」，再碰标签。

六、网络要求（重要：防火墙）
  手机与电脑需在同一局域网。电脑端做 UDP 组播/广播 + BLE 广播，手机按
  「标签候选 → 缓存 → BLE → UDP 组播 → 子网扫描」顺序寻找电脑。
  实测若两端跨 /24（例如电脑 192.168.1.x、手机 192.168.2.x），UDP 组播不跨网段，
  此时需要：标签 URI 带 &c=<电脑IP> 候选，或手机通过蓝牙 BLE 收到广播。
  这是网络环境约束，不是程序缺陷。
  ★ 首次启动会弹 Windows 防火墙提示，必须点「允许访问」。若误点了「阻止」，
    手机会一直提示找不到电脑，而桌面端本机状态显示服务已启动。
    修复：Windows 安全中心 → 允许应用通过防火墙 → 勾选安装目录里的 NfcTapLink.exe；
    或管理员命令行：
      netsh advfirewall firewall add rule name="NfcTapLink 允许入站" dir=in
        action=allow program="C:\...\NfcTapLink.exe" enable=yes profile=any
    防火墙规则按 exe 完整路径生效，换安装目录后需重新允许一次。
  ★ 不要同时开两个一碰传；同一端口只允许一个实例。

七、安全模型（v3 / 6.2.4）
  1. 标签里的 k 是本机随机生成的 256-bit 配对密钥；k 永不上网。
     配对走 /api/challenge + /api/pair 双向挑战应答：
     手机用 k 签 proof，电脑回 server_proof 证明自己也持有 k。
     假服务没有 k，无法冒充电脑；发现层广播无签名，也不被当作身份证明。
     k 只允许出现在物理标签与手机输入框里：不进 URL 查询串、不进访问日志。
  2. token 有状态、随机、绑定来源 IP、10 分钟过期、服务端重启即失效。
     401/403 时手机端自动重新挑战应答一次，无需用户干预。
  3. 上行（手机→电脑）与下行（电脑→手机）双向都做应用层加密
     （HMAC 计数器密钥流）与 encrypt-then-MAC 防篡改；两者的密钥与 AAD
     完全域分离（upload| 与 download|、POST 与 GET 各用一套），互不可复用。
     AAD 绑定 token / 路径 / 时间戳 / nonce / 文件名 / 数据长度，nonce 一次性。
     明文 HTTP 被嗅探也拿不到文件内容或 k。
  4. 下行额外做两道校验：服务端返回 X-SHA256，手机端解密后重算摘要比对，
     不一致直接丢弃不落盘；同一待发文件被标记已接收后再次请求返回 409。
  5. 服务端校验 Host（仅 IP 字面量/localhost）、Origin、Sec-Fetch-Site；
     状态页全部字段 HTML 转义 + CSP；/api/recent 需 token；/api/pair 限速。
     发布包不含密钥，Android release 用正式 keystore 且 minify + allowBackup=false。
  6. 收发的文件只落本地目录，不上传云端、不自动执行。

八、卸载
  开始菜单 → 一碰传 → 卸载 一碰传，或「设置 → 应用」里卸载。
  卸载只移除程序文件，不删除已接收的文件、日志与本机配对配置。
